# Sponsors & Referral Attribution — v2.3

## Purpose
Track which ecosystem/community/partner originated a user and measure the downstream product usage generated by that channel.

Examples of sponsor records may include communities, academies, media brands or ecosystem partners. Sponsor identity is a business object and is separate from the end-user identity.

## Attribution model
Default: immutable **first-touch**.

A principal that first arrives through sponsor A remains attributed to A unless an operator deliberately changes the database record. This prevents later links from overwriting acquisition attribution.

Accepted attribution inputs:
- `https://skills.norug.es/r/<sponsor-or-campaign-code>`
- `nr_ref` cookie (90 days)
- `x-norug-referral-code`
- `x-sponsor-code`

## Sponsor hierarchy
`sponsor` → zero or more `campaigns` → pseudonymous referred principals → sessions/calls/services.

Example:
- Sponsor: `madbitcoin`
- Campaigns: `madbitcoin-youtube`, `madbitcoin-event-2026`

## Internal control
`/Dashboard/Sponsors` creates sponsors and returns two secrets/identifiers:
- referral URL
- sponsor portal token

The portal token is only returned at creation in the prototype. Store it securely.

Internal operators can measure:
- referred principals
- activation/active users
- sessions
- calls
- top services / skills / capabilities
- campaign performance
- pseudonymous user-level activity

## Sponsor-facing portal
`/Sponsor` exposes only aggregate metrics for the authenticated sponsor:
- referred users
- active users
- sessions
- calls
- top services
- campaign performance

It does not expose other sponsors, raw prompts, wallet searches, IP-derived hashes or individual traces.

## Database
Migration: `db/migrations/002_sponsors_referrals.sql`.

Tables:
- `sponsors`
- `sponsor_campaigns`
- `referral_attributions`

`gateway_events` receives `sponsor_id`, `campaign_id`, and `referral_code` for fast analytics.


## Optional consented lead profile
The runtime can keep users pseudonymous forever. If a user explicitly opts in to commercial contact, `POST /api/v1/referrals/profile` can store display name/email/company linked to the pseudonymous principal. Contact fields are rejected unless `marketing_consent=true`. Sponsor-facing dashboards do not expose these profiles by default.
